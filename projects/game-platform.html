Multiplayer Game Platform

JavaFX LAN Game Platform Built With a Large Software Engineering Team

View Code

Overview

This was a large SENG 300 team project: a Java desktop platform for playing Tic Tac Toe and Connect Four over a LAN. The app includes account login, persistent sessions, public and private lobbies, matchmaking, chat, bot opponents, Elo ratings, leaderboards, draw and resign flows, and post-game results.

The project used JavaFX as the desktop shell and loaded HTML/CSS screens through WebView. Java bridge classes expose backend behavior to JavaScript, while a TCP client/server layer keeps lobbies and games synchronized between players.

How It Works

  • JavaFX WebView Shell

    MainApp loads HTML screens into a WebView. Bridge classes attach Java objects to the browser window so JavaScript can call into Java for login, lobby, matchmaking, game, leaderboard, and results actions.

  • LAN Networking

    The client discovers servers with UDP broadcast or subnet scan, then connects over TCP. Requests and responses are serialized payload objects routed through client and server handler registries.

  • Lobby and Match Flow

    LobbyManager tracks join codes, public and private rooms, ready state, player membership, bot players, and disconnect cleanup. Matchmaking pairs players by game type and Elo rating.

  • Game State Sync

    Tic Tac Toe and Connect Four share a GameAbstract base with board state, piece ownership, current player tracking, move results, draw offers, resigns, and win validation.

  • Bots and Ratings

    Bots use difficulty-scaled forced move detection and a possibility tree with alpha-beta pruning. Post-game logic computes Elo deltas and routes players to the results screen.

Architecture

Bridge Layer

GameBridge, LobbyBridge, AccountBridge, MatchmakingBridge, and related classes translate UI actions into typed backend calls and push backend updates back into JavaScript.

Network Layer

Client and Server use Java sockets, object streams, routers, and typed payload classes to move protected requests and pushable responses across the LAN.

Platform Core

LobbyRoom, LobbyManager, MatchmakingManager, Player, Bot, EloCalculator, and game classes define the shared domain state used by the UI and server handlers.

Persistence and Tests

Serializable file-backed database classes store accounts, sessions, lobbies, and leaderboard data. JUnit tests cover database behavior, networking, lobbies, bridges, validation, and bots.

Team Credit

Shoutout to the classmates who built and debugged this with me. The project had many moving parts, and the UI, validation, game logic, bot logic, tests, and documentation all depended on different people getting their parts working and then helping integrate them under deadline pressure.

Limitations

This was a course project optimized for local demos and team integration. Persistence is file-based serialization rather than a production database, networking is LAN-oriented, and the JavaFX WebView UI is desktop-only.
