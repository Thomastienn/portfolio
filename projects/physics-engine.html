Overview

This is Jacob Behnam's custom physics simulation and visualization tool. It combines a C++ physics core with a Qt/OpenGL editor-style interface for building scenes, running simulations, inspecting objects, saving and loading scenes, and visualizing motion.

My contribution was scoped and mostly focused on optimization experiments. I helped add spatial acceleration structures for gravity, thermal proximity, and collision broad-phase checks, plus smaller support work around thermal properties, snapshots, debug visuals, scene presets, and Linux setup.

The main code I would point to is the octree in src/physics/spatial/Octree.* and the collision BVH in src/physics/spatial/BVH.*. The physics loop builds those structures each step, uses the octree for approximate pairwise gravity and heat transfer, and uses the BVH to filter collision candidates before narrow-phase checks.

I also made smaller contributions around temperature fields in the physics model and UI, snapshot interpolation for smoother rendering, debug overlays, sample scene/preset work, and Linux build/run scripts.

How It Works

  • Octree for N-Body Work

    The octree groups bodies by position and stores aggregate mass, center of mass, effective thermal area, and emission. Distant nodes can be approximated instead of checking every body pair directly.

  • BVH for Collision Broad Phase

    The BVH builds AABB bounds around collidable bodies, recursively splits by the widest centroid axis, and returns possible collision pairs for the narrow-phase collider logic.

  • Physics Loop Integration

    PhysicsSystem rebuilds the octree during each advance step, applies global and n-body gravity, updates thermal properties, records snapshots, then runs BVH-filtered collision checks.

  • Editor and Debug Support

    The app includes scene hierarchy and inspector panels, object labels/focus tools, path and force visualizations, collider debug views, snapshot history, and sample scenes.
