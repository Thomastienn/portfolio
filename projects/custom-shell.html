Custom Shell

Rust Shell with Custom Parsing, Terminal Editing, and Process Control

View Code

Overview

Custom Shell is a Rust implementation of a Unix-style command shell. It handles the core pieces that make a shell feel real: parsing commands, routing stdin and stdout, launching external programs, running builtins, tracking background jobs, and keeping an interactive terminal input loop responsive.

The project is not presented as a complete production shell. The valuable part is the systems work: turning raw user input into structured commands, passing execution state through a dispatcher, and coordinating child processes with terminal behavior.

Key Pieces

Parser command grammar
Jobs background process state
Raw TTY interactive input

The tokenizer recognizes words, quotes, escapes, variables, pipes, redirection operators, file descriptors, and background commands. The parser turns those tokens into command structures with stdin, stdout, stderr, pipeline, and background execution metadata.

How It Works

  • Tokenizer and Parser

    Input is split into structured tokens, then parsed into command objects that carry arguments plus stdin, stdout, stderr, pipe, redirect, and background-job information.

  • Terminal Input

    The input loop uses raw terminal mode for character-level handling, history navigation, backspace rendering, Ctrl-C behavior, syntax-colored redraws, and tab completion.

  • Command Dispatch

    Builtins and external commands share a common runnable interface. The dispatcher routes parsed commands, forwards pipeline output, waits for child processes, and returns shell exit state.

  • Pipes and Redirection

    Stdio helpers convert parsed input and output targets into process handles, files, append targets, inherited streams, or pipe endpoints for both external commands and builtin output.

  • Jobs and Completion

    Background processes are stored with job IDs and checked with nonblocking waits. Completion uses command and filesystem tries, with support for command-specific completion scripts.

Architecture

Parsing Layer

tokenizer.rs and parser.rs separate lexical concerns from command assembly, keeping execution code from handling raw strings directly.

Execution Layer

The runnable trait gives builtins and external commands a shared shape, while the dispatcher manages pipes, background execution, and shell exit handling.

Interactive Layer

input.rs owns raw-mode terminal behavior, redraws the prompt after edits, and chooses between command, filesystem, and custom completion sources.

State Layer

The shell keeps command tries, filesystem completion data, background jobs, command history, completion registrations, and shell variables in one context passed through each command.
